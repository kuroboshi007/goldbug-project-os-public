# goldBug Project OS

`goldBug Project OS` は、k.goldbug.studio と AI 協力者が作成した、小規模でバージョン管理できるプロジェクトのルール、手順書、テンプレート集です。

[English](README.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md)

## 対象となる利用者

会話が変わっても、プロジェクトの範囲、現在の状態、採用済みの決定、レビューの責任、引き継ぎを明確に保ちたいメンテナーと AI 協力者向けです。最小限のテンプレートをプロジェクトにコピーして確認済みの事実を記入し、手順書に沿って作業を進めます。

これはプロジェクトを運営するための仕組みであり、コンピューターの OS やインストールするアプリではありません。プロジェクトの作成、エージェントの実行、ノートの同期、リポジトリの公開を自動で行うものではありません。公開ソースリポジトリ：[goldbug-project-os-public](https://github.com/kuroboshi007/goldbug-project-os-public)。

3 つの README は同じ内容の入門ガイドです。リンク先のルールとテンプレートは現在英語です。[AGENTS.md の正式な読む順序](AGENTS.md#required-read-order)に従い、設定や方針の詳細はリンク先の文書で確認してください。

## 必要なツール

- 付属スクリプトには Bash、Git、jq、標準の `head` が必要です。
- テストには Python 3.9 以降が必要です。
- 独自のタイムゾーンには、信頼できるインストール済み IANA zoneinfo データが必要です。既定の `Etc/UTC` には不要です。
- GitHub リポジトリとアクセス権は issue／PR の作業手順を採用する場合に必要です。ローカルのクイックスタートにノートのアカウントや任意サービスは不要です。

スクリプトは Bash 環境で実行します。ネイティブ Windows での実行は未検証なので、使用環境のツールとタイムゾーンデータを確認してください。以下のオフラインリンク検査には、任意で `lychee` を利用できます。

## 最小限のローカルクイックスタート

この README があるディレクトリで実行します。例では隣に新しいディレクトリを作成します。`../my-project` が既に存在する場合は、上書きせず別の新しい名前を選んでください。

```bash
bash scripts/project-os-config.sh &&
mkdir ../my-project &&
cp templates/AGENTS.md templates/PROJECT.md templates/STATUS.md templates/DECISIONS.md ../my-project/
```

プロファイルが選択されていなければ、最初のコマンドは `configuration source: off — no configuration` を出力します。新しいディレクトリには 4 つの文書が入ります。

| ファイル | エージェントに作業を依頼する前に記入する内容 |
| --- | --- |
| `AGENTS.md` | プロジェクト名、権限、安全ルール、検証コマンド、実際に参照できる共通方針の場所／checkout のヒント |
| `PROJECT.md` | 利用者、目標、対象外の範囲、技術構成、既知の検証コマンド |
| `STATUS.md` | 現在の状態、次の作業、障害、リスク |
| `DECISIONS.md` | 採用済みの決定。未決事項は未確認のままにする |

テンプレートの仮置き文字列を確認済みの情報に置き換え、不明な点は `To confirm` と記します。仮置き文字列を URL、コマンド、Git の身元情報として実行してはいけません。公開 upstream URL は想定していません。`upstream.url` が未設定なら clone を保留します。エージェントには、プロジェクトの指示と文書を読んだうえで、範囲を限定した 1 つのタスクと検証計画を提案するよう依頼します。タスク、引き継ぎ、ADR のテンプレートは必要な場合だけ追加します。Claude を使う場合は `templates/CLAUDE.md` もコピーできます。

既存のプロジェクトでは、現在の文書と安全ルールを先に確認して対応づけ、無条件に置き換えないでください。導入全体、作業手順のファイル、レビューについては [Bootstrap a Project](playbooks/bootstrap-project.md)を参照してください。

## 設定と非公開情報

プロファイルは必須ではありません。既定では中立的なメンテナー表記、`Etc/UTC`、ノートモード `none` を使い、コミット email の強制、portfolio、任意のお知らせサービスは無効です。

新しいローカルコピーを設定するには、[合成された例](.config/project-os.example.json)を参考に、Git が無視する `.config/project-os.local.json` を作成します。最小の有効なプロファイルから始めることもできます。

```json
{"schema_version": 1}
```

既存のローカルプロファイルは上書きせず編集してください。OS ディレクトリで検証します。

```bash
bash scripts/project-os-config.sh
```

ローカルプロファイルが選択されると `configuration source: on — local profile` を出力します。プロファイルは次の優先順位で丸ごと選ばれ、項目は混合されません。

```text
PROJECT_OS_PROFILE → .config/project-os.local.json → private/project-os.json → built-in defaults
```

公開候補版には非公開の試行プロファイルを含めていません。完全な例は架空のデータなので、サービスを有効にする前に宛先を置き換えてください。非公開の宛先や実際のプロジェクト一覧を公開内容に含めず、どのプロファイルにも認証情報を保存しないでください。選択したプロファイルが存在しない、読めない、不正な JSON、または無効な内容の場合、依存する作業は停止します。既定値に切り替えてエラーを回避してはいけません。[設定の契約](docs/configuration.md)を参照してください。

タイムゾーンには `Asia/Tokyo` や `America/New_York` など、IANA の標準的な `Area/Location` 名を推奨します。`US/Eastern` などの旧エイリアスは、ホストの信頼できる zoneinfo データベースに対応する読取可能な TZif ファイルがある場合だけ利用できます。利用可能なエイリアスはホストによって異なります。既定の `Etc/UTC` は特別な既知の値です。Windows の表示名、前後の空白、制御文字、パストラバーサルは、文字列を整形せず拒否します。必要な場合だけ信頼できる `TZDIR` データを指定してください。検証するのは名前／ファイルの存在と TZif magic であり、UTC offset、夏時間、TZif 全体の構造、データの真正性は検証しません。[タイムゾーン検証](docs/configuration.md#timezone-validation)を参照してください。

## 任意の連携

[ノートモード](docs/notes.md)の既定値は `none` です。アカウント、宛先、要約の配信、未完了の同期は不要です。`markdown` は承認されたフォルダー向けに確認済みの要約を準備します。`notion` には、承認済みのサービスへのアクセスと、設定された宛先／schema が必要です。外部への書き込み前には確認と配信のルールに従ってください。プロファイルやスクリプトは自動同期を行いません。

Portfolio の追跡とお知らせチャンネルは任意で、既定では無効です。設定でチャンネルを有効にしても、各製品が使用するかどうかを明示的に決めます。共通サービスは全プロジェクトの必須依存ではありません。[プロジェクトのライフサイクル](docs/project-lifecycle.md)と[お知らせチャンネル](knowledge/shared-announcement-channel.md)を参照してください。

## 作業手順と役割

1. メンテナーが成果を承認し、製品、プライバシー、公開、マージに関する重要な判断を行います。
2. エージェントが範囲を限定した GitHub issue を作成し、ブランチで実装して draft PR を開きます。
3. 別のエージェントが変更全体と証拠をレビューします。
4. メンテナーが残る判断を解決してマージします。
5. 確認済みの情報だけに選択したノートモードを適用し、再利用できる学びは別の OS issue／PR で取り込みます。

GitHub は作業の記録、プロジェクト文書はプロジェクトの事実と採用済みの決定を保持します。ノートは確認済みの人向け要約であり、別のタスク状態を作りません。引き継ぎでは OS revision と configuration source を記録します。エージェントのコミットは[作成者の印](AGENTS.md#authorship-marks)にある製品名つきの連続した trailers に従います。表示用のプロファイル項目は Git の身元情報を設定しません。[運営モデル](docs/operating-model.md)、[協力の手順](docs/ai-collaboration.md)、[レビュー](playbooks/review-change.md)も参照してください。

## 検証とエクスポート

OS ディレクトリで付属のテストを実行します。テストは隔離された合成フィクスチャを使います。

```bash
python3 tests/test-core-review.py
python3 tests/test-export.py
```

エクスポートにはコミット済みの Git checkout が必要です。展開したアーカイブには Git 履歴がありません。エクスポートするには、自分の確認済みの公開用身元情報を使ってローカル Git を初期化し、レビュー済みのスナップショットをコミットしてください。エクスポーターは Git の初期化、身元情報の選択、コミット、公開を行いません。対象ファイルの変更を先にコミットし、新しい出力先を指定します。

```bash
bash scripts/export-candidate.sh ../public-candidate
```

明示的な[許可リスト](export/manifest.txt)には 3 つの README と `LICENSE` が含まれます。各ファイルは取得したコミットから読み込み、実行権限を保持します。`PROJECTS.md` は合成された一覧、`archive/README.md` は埋め込まれた汎用テンプレートを使います。非公開プロファイル、ローカル設定、履歴、リスト外のファイルは除外します。既存の出力先、安全でないパス、シンボリックリンク、対象ファイルの未コミット変更は拒否します。Git に追加しただけではエクスポート対象になりません。

`lychee` がインストールされている場合、文書で指定されたオフライン検査は次のとおりです。

```bash
lychee --offline --no-progress --include-fragments --exclude-path 'archive/' './**/*.md'
```

実際に出力された内容、権限、リンク、ファイル名、プライバシーを別途確認してください。Git はファイルシステムの xattrs、resource forks、所有者を保存しません。フォルダーをそのままアーカイブすると metadata sidecars が含まれる可能性があります。このツールはローカルファイルのエクスポートであり、アーカイブやプライバシーの認証ではありません。[エクスポートのレビューとパッケージ化の制限](docs/export.md)を参照してください。

## リポジトリの構成

`AGENTS.md` は共通ルール、`docs/` は方針、`playbooks/` は手順、`templates/` はプロジェクト用の最小セットです。`knowledge/` は再利用できる学びや候補を保持しますが、自動的に現行方針にはなりません。`archive/` は履歴であり、現在の根拠ではありません。出力される `PROJECTS.md` は合成された例で、実際の portfolio ではありません。
